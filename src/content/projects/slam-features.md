# 기능 개발

## 1. 스마트 라벨링

**문제** — Segmentation 라벨링은 객체 외곽을 사람이 일일이 클릭해 폴리곤을 찍어야 해서,
한 장당 작업 시간이 길고 작업자 피로도가 높습니다.

**개발** — 이미지에서 객체를 클릭하면 외곽을 자동으로 따 폴리곤을 생성하는 기능을
개발했습니다. 프로젝트에 학습된 모델이 아직 없는 초기 단계에서도 쓸 수 있도록,
사전학습 모델 기반의 기본 객체탐지를 함께 제공해 첫 라벨링부터 자동 분할이 동작합니다.

**효과** — 수작업 클릭이 클릭 한 번으로 대체돼, 라벨링 초기 구간의 작업 속도가
크게 단축됐습니다.

## 2. 오토 라벨링

**개발** — 프로젝트에서 학습이 완료된 모델을 골라, 아직 라벨링되지 않은 이미지들에
클래스별 객체 탐지를 일괄 수행하는 기능입니다. 추론 결과는 바로 확정되지 않고
라벨 후보로 올라가, 작업자가 검수·수정한 뒤 확정하는 흐름으로 설계했습니다.

**구현** — 이미지 수가 많으면 요청 시간 안에 처리할 수 없기 때문에, 추론은 Celery
비동기 태스크로 분리하고 진행 상태를 폴링해 확인하도록 구성했습니다.

**효과** — 라벨링 → 학습 → 오토 라벨링 → 검수로 이어지는 순환이 만들어져,
데이터가 쌓일수록 사람이 손댈 작업량이 줄어듭니다.

## 3. 라벨링 연동 자동 모델 학습

**개발** — 라벨링 작업이 일정량 쌓이면 별도 조작 없이 학습이 시작되는 파이프라인을
백엔드에서 담당했습니다. 학습 요청은 Celery·RabbitMQ 큐를 거쳐 GPU 워커로 전달되고,
데이터셋 스냅샷 생성 → 학습 실행 → 결과 모델 등록까지가 하나의 흐름으로 처리됩니다.

**지원 태스크** — 2D Detection, Segmentation

**의미** — "라벨링을 하면 모델이 만들어진다"는 서비스의 핵심 가치를 실제로 성립시키는
부분으로, 사용자는 ML 파이프라인을 몰라도 라벨링만으로 모델을 얻습니다.

## 4. DGX-Spark 온프레미스 배포 구성

**배경** — 고객사 반입용으로, 전체 서비스 스택을 단일 장비(DGX-Spark)에 담아
전원만 켜면 운영되는 "원박스" 형태가 필요했습니다.

**구성** — API·워커·DB·브로커·파일 스토리지(MinIO)를 Docker Compose 단일 스택으로
묶고, GPU 워커가 장비의 로컬 GPU를 그대로 사용하도록 구성했습니다. 외부와 단절된
폐쇄망 환경을 전제로, 이미지·모델 가중치 등 필요한 자산을 사전 반입하는 형태로
설계했습니다.
