# 프론트엔드·운영

## 어드민 대시보드 (프론트 약 30~40% 담당)

React + TypeScript + Ant Design + React Query 기반 어드민에서 아래 화면을 개발했습니다.

- **참가자 수집 타임라인** - ECharts로 레인별 수집 현황 시각화, 화면 상호작용 레인·앱별 이모지 표시
- **자료 내려받기** - 연구·참여자·설문 회차 단위 내보내기 요청과 파일 다운로드
- **EMA 설문 편집** - 시각·숫자 문항, 조건부 표시, 복수 선택 제한, 객관식 '기타(직접 입력)' 관리
- **알림 설정** - 알림 시각별 응답 가능 시간 설정 모달
- **웨어러블 관리** - 기기 배정·회수·삭제와 이력 조회

## E2E 테스트

Playwright로 주요 흐름을 E2E 테스트로 작성했습니다.

- 설문 EMA 문항, '기타' 문항, 응답 있는 설문의 수정 잠금, 응답 가능 시간
- 웨어러블 배정·삭제

## 운영 기능 (백엔드)

- 참여자 엑셀 일괄 등록, 연구원 계정 관리(Keycloak Admin API)
- 담당자·수집 현황 조회, 수집 권한 스냅샷, 설치 앱 목록 수집
- 통화·문자 상대 번호-연락처 매핑
- 웨어러블 기기 대장(배정·회수·이력)

## 배포

- **백엔드** - arm64(Graviton) 이미지를 빌드해 ECR에 푸시 → 태스크 정의 새 리비전 등록 → ECS 서비스 갱신 후 안정화까지 대기. 이미지 태그는 빌드 시각 기준
- **프론트** - 빌드 결과를 S3에 동기화하고 CloudFront 캐시 무효화. CloudFront 한 도메인에서 `/api/*`는 ALB(백엔드)로 보내 프론트·API를 같은 출처로 제공
- **환경 분리** - dev/prod/로컬 env를 나누고, 운영은 `make release`, 개발 서버는 별도 명령으로 배포

## 참여자 앱 배포

수집 앱은 통화·문자 기록, 접근성 서비스 같은 권한을 쓰는데, 이런 권한은 스토어 정책상 연구 목적으로 배포할 수 없습니다.
그래서 스토어를 거치지 않고 APK를 직접 배포하는 경로를 만들었고, 자체 설치(사이드로딩)가 가능한 Android 전용으로 운영합니다.

- **버전별 보관** - 빌드번호(versionCode)를 배포 번호로 삼아 `ssk-phenotype-<빌드번호>.apk`로 S3에 버전마다 남김. 같은 번호로는 다시 올리지 못하게 막아, 한 번 나간 번호의 내용이 바뀌지 않고 참가자 폰마다 어떤 빌드가 깔렸는지 추적 가능
- **고정 주소 + QR** - 릴리스마다 `latest.apk`를 덮어써 QR이 가리키는 주소는 그대로 유지. QR을 다시 만들거나 나눠줄 필요 없이 항상 최신 앱을 받음
- **캐시 분리** - 버전 파일은 내용이 바뀌지 않아 장기 캐시(immutable), `latest.apk`·`latest.json`은 no-cache로 옛 APK가 나가지 않게 함. APK content-type을 지정해 브라우저가 설치 파일로 인식
- **매니페스트** - `latest.json`에 빌드번호·크기·sha256·배포 시각을 함께 올려, 어드민 화면이 QR 옆에 현재 배포 번호를 표시
- **명령 하나로 배포** - `make app-release`로 빌드번호 증가 → 빌드 → 업로드 → 매니페스트 갱신까지 실행
